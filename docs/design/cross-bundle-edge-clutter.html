Cross-bundle edges are eating the canvas

Five ways to fix the zoomed-out view of a large colocated bundle graph, with live mock renders. All diagrams share one synthetic graph: 6 bundles, 96 concepts, 74 cross-bundle links. Drag the zoom slider at the top to see how each option behaves at overview vs. reading distance.

What actually goes wrong

In src/visualize.ts the edge pass runs before the node pass, but every cross-bundle edge is drawn at globalAlpha 0.9, in saturated gold, 1.6 / view.k wide, dashed, with an arrowhead. Three separate things compound at low view.k:

  • Screen-space constant width. Dividing by view.k means zooming out does not thin the lines. Node radii, by contrast, shrink with the world. Ink per screen pixel climbs as you zoom out.
  • Highest contrast is given to the highest-count element. Gold at 0.9 alpha against #11151c is the loudest thing on the canvas, and in a colocated graph cross-bundle edges are the most numerous thing on the canvas.
  • Dashes and arrowheads add ink without adding information at overview scale. A 5px dash gap is invisible at k=0.5 but the arrow triangles are still filled at full alpha, so dense targets grow a gold halo.

So the fix is not one knob. Each variation below picks a different lever: aggregate the lines, quiet them, route them, gate them, or replace them.

This page renders its diagrams with an inline script. With scripts off you still get the full written spec for each variation; only the canvases are blank.

Baseline: what ships today

Current renderer. At k below ~0.8 the gold mesh is opaque enough that cluster shape, node size, and community color are all guesses.

A. Semantic zoom: bundle-pair trunkshighest payoff

Below the threshold, all cross edges between a bundle pair collapse to one trunk whose width encodes the count. Push the slider past ~1.0 and individual edges cross-fade in.

How

Group cross edges by unordered bundle pair once, after layout settles. Draw one line per pair between the two community centroids, width proportional to sqrt(count), plus a small count label. Cross-fade on view.k so nothing pops.

const t = clamp((view.k - 0.85) / 0.5, 0, 1);
// trunks at (1 - t), individual cross edges at t

Centroids are already computed every tick for cluster gravity, so the extra cost is one pass over edges per frame.

Trade

  • The overview answers the question people actually zoom out to ask: which bundles talk to each other, and how much?
  • Individual provenance is unavailable at overview scale by design. Mitigate by making a trunk clickable to list its member edges in the details panel.
  • Needs a stable community centroid, so it is coupled to CommunityMode. In type or tag mode the trunks mean something different, which may be fine or may need to be disabled outside bundle mode.

B. Quiet by default, loud on demandcheapest real fix

Cross edges drop to a low-alpha neutral and lose the dash; one node is shown in a simulated hover state, and gold rim ticks mark every node that has external links so the information survives the fade.

How

Invert the current emphasis. Cross edges become the quietest layer, not the loudest, and the gold is spent on the node rim instead of the line:

ctx.globalAlpha = (e.cross ? 0.16 : 0.5) * a;
ctx.strokeStyle = e.cross ? "#8a7a45" : "#7d8590";
ctx.lineWidth   = (e.cross ? 1.1 : 1) / view.k;
ctx.setLineDash([]);            // drop dashes entirely
// arrowheads only when view.k > 1

Then draw a gold arc on each node's rim sized by its cross-degree, and light the full cross edges to alpha 0.95 for the hovered or selected node only. Legend focus keeps its current "either endpoint" rule.

Trade

  • Small diff, no new data structures, no layout coupling. This is the one to ship first.
  • Cross-bundle structure is no longer readable passively; you have to point at something. For a graph this dense that is arguably correct, but it is a real loss for screenshots.
  • Rim ticks recover the "this concept reaches outside its bundle" signal at zero line cost, and they scale with the world, so they never dominate.

C. Bundled corridorsmoderate

Same edges, same alpha as today, routed as quadratic curves pulled toward their bundle-pair axis. Parallel links merge into a few readable corridors instead of a uniform crosshatch.

How

A cheap approximation of hierarchical edge bundling: for each cross edge, take the midpoint of the two owning centroids, then pull the quadratic control point most of the way toward it.

const m  = midpoint(centroid[src.community],
                    centroid[dst.community]);
const cx = lerp(midpoint(src, dst).x, m.x, 0.85);
ctx.quadraticCurveTo(cx, cy, dst.x, dst.y);

Optionally offset each corridor slightly by pair index so overlapping corridors between different pairs stay separable.

Trade

  • Keeps every individual edge visible and traceable, which A and B both give up. Best option if someone's job is following a specific link across bundles.
  • Preserves ink volume. It reorganizes clutter rather than removing it, so with 6+ bundles and hundreds of cross edges the corridors themselves get crowded.
  • Curves cost more per frame than lines, and the arrowhead math has to use the curve tangent rather than the straight-line direction.
  • Pairs well with B's alpha reduction; on its own it does not solve the zoomed-out case.

D. Explicit layer controlssmallest diff

Mocked control strip drawn into the canvas. Cross edges render under everything at a user-set opacity, with arrowheads and dashes as separate toggles.

How

Add four checkboxes and one slider to #panel, below the legend: intra-bundle, cross-bundle, arrows, labels, plus a cross-edge opacity slider defaulting to about 0.25. Multiply the slider into the existing per-edge alpha and skip the arrowhead block when the toggle is off.

The one structural change worth bundling in here: keep the edge pass strictly beneath the node pass and stop drawing arrowheads while view.k < 1, since a filled triangle at overview scale is pure noise.

Trade

  • Half an hour of work, no algorithmic risk, and it makes every other variation easier to evaluate because you can A/B by dragging a slider.
  • Pushes the problem onto the reader. A good default still matters; controls are not a substitute for one.
  • Panel real estate is finite, and the panel is already carrying stats, search, and a legend that grows with bundle count.

E. Two-level graph with drill-downlargest change

Zoomed out, the graph is the bundle meta-graph: one node per bundle sized by concept count, weighted arcs between them. Zoom past the threshold and concepts appear.

How

Build a second graph at export time: nodes are bundles, edges are pair counts. Render the meta-graph alone below k ≈ 0.9, cross-fade to the concept graph above it, and cull concept nodes outside the viewport so large exports stay at 60fps. Clicking a bundle node zooms to fit that cluster.

The force simulation is O(n²) per tick today; this is also the natural place to fix that, since the meta-graph only needs to settle over a handful of nodes.

Trade

  • The only option that genuinely scales past a few thousand concepts. It changes what the overview means rather than trying to make a hairball legible.
  • Biggest implementation surface: second layout, transition state, viewport culling, and a new interaction model on top of the existing pan/zoom/select.
  • A single-bundle export degenerates to one node, so the meta level needs to be suppressed unless the export spans multiple bundles.
  • For very dense pairs, a bundle-by-bundle adjacency matrix beside the graph reads better than arcs and is easy to add once the pair counts exist.

Recommendation

Ship D, then B, then A. They compose into one coherent design rather than three competing ones:

  • D first, as scaffolding. The toggles and the opacity slider cost almost nothing and let you tune the defaults for the other two empirically instead of by argument. Fold in the two unambiguous fixes while you are there: edges strictly under nodes, no arrowheads below k=1.
  • B next, as the new default. Cross edges become the quiet layer, the dash goes away, and the gold moves to node rim ticks. This alone makes the current screenshots readable.
  • A last, as the overview payoff. With B's alpha already low, trunks read cleanly on top and turn the zoomed-out view into a real bundle-dependency diagram.

Hold C unless someone reports needing to trace individual cross-bundle links at a distance; it is the wrong tool for the reported problem, which is overview legibility. Hold E until export size actually hurts frame rate, at which point the O(n²) tick loop is the more urgent half of that work anyway.
